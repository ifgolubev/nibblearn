# Getting started

Nibblearn is a React library for interactive learning content: flashcards, matching, branching scenarios, simulations and more. Every module is driven by a JSON config validated with Zod, so content can be written by hand, generated by an LLM, or built from TypeScript objects with full autocompletion.

Two packages:

| Package            | What it contains                                                                                                                              |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `@nibblearn/react` | Components for all 22 modules, `LessonPlayer`, `NibblearnProvider`, primitives, one stylesheet. Re-exports everything from `@nibblearn/core`. |
| `@nibblearn/core`  | Framework-agnostic schemas, `validateLesson`, scoring, progress storage, events, i18n messages. No React dependency.                          |

Package names are provisional; see [Releasing](./release.md) for the naming note.

## Install

```bash
npm install @nibblearn/react
# or
pnpm add @nibblearn/react
# or
yarn add @nibblearn/react
```

Peer dependencies: `react` and `react-dom` at `^18.2.0 || ^19.0.0`. `@nibblearn/core` is installed automatically as a dependency; add it explicitly only if you want to validate content in a non-React environment (a Node script, an API route).

## Import the stylesheet

Nibblearn ships one scoped stylesheet. Every class is prefixed `nb-` and every token `--nb-`, so it does not leak into your app and does not require Tailwind or any CSS framework.

```ts
import "@nibblearn/react/styles.css";
```

Import it once, at the root of your app (`main.tsx`, `App.tsx`, or `app/layout.tsx` in Next.js).

## Add one interactive module to an existing page

### Option A: a typed component

Each module is a React component that takes a `config` prop. Parse the config with the module schema so defaults are applied and TypeScript knows the exact shape.

```tsx
import "@nibblearn/react/styles.css";
import { Flashcards, flashcardsSchema, type FlashcardsInput } from "@nibblearn/react";

const deck = {
  id: "metric-deck",
  type: "flashcards",
  title: "Metric deck",
  instructions: "Flip each card, then rate yourself honestly.",
  content: {
    cards: [
      {
        front: "CPM",
        back: "**Cost per mille** — what you pay for 1,000 impressions.",
        tag: "Cost",
      },
      {
        front: "CTR",
        back: "**Click-through rate** — clicks ÷ impressions.",
        tag: "Rate",
        hint: "Compares two counts.",
      },
      { front: "ROAS", back: "**Return on ad spend** — revenue ÷ spend.", tag: "Return" },
    ],
  },
} satisfies FlashcardsInput;

export function Glossary() {
  return (
    <Flashcards
      config={flashcardsSchema.parse(deck)}
      onComplete={(result) => console.log("done", result.score)}
    />
  );
}
```

`satisfies FlashcardsInput` gives you autocompletion and type errors while writing the object. `flashcardsSchema.parse()` turns the input (optional fields omitted) into the parsed config (defaults filled in) that the component expects. Every module exports the same trio: `XxxInput`, `XxxConfig`, `xxxSchema`.

`defineModule()` does the same in one step and narrows the type from the `type` field, so the result can go straight into the matching component:

```tsx
import { Flashcards, defineModule } from "@nibblearn/react";

const deck = defineModule({
  id: "metric-deck",
  type: "flashcards",
  content: { cards: [{ front: "CTR", back: "Click-through rate" }] },
}); // typed as FlashcardsConfig; throws LessonValidationError if invalid

<Flashcards config={deck} />;
```

If you pass an invalid config at runtime, the component renders an inline error listing each problem instead of crashing.

### Option B: JSON through `ModuleRenderer`

When content comes from a CMS, a file or an LLM, you do not know the module type ahead of time. `ModuleRenderer` picks the right component from the registry by the `type` field.

```tsx
import { ModuleRenderer, defineModule } from "@nibblearn/react";
import quizJson from "./quiz.json";

// defineModule validates and throws a LessonValidationError with readable paths.
const quiz = defineModule(quizJson);

export function Quiz() {
  return <ModuleRenderer config={quiz} onComplete={(r) => console.log(r)} />;
}
```

`ModuleRenderer` accepts the same props as any module (`config`, `onComplete`, `onEvent`, `resetKey`, `hideHeader`, `className`) plus `registry` and `fallback` (shown while a lazy module loads). If you prefer not to throw, use `validateModule(json)` and inspect `result.issues`.

## Build a whole lesson

A lesson is an ordered list of module configs plus a few settings. `LessonPlayer` renders the intro screen, navigation, progress persistence, scoring and the summary.

```tsx
import { LessonPlayer, defineLesson } from "@nibblearn/react";

const lesson = defineLesson({
  schemaVersion: 1,
  id: "metrics-101",
  title: "Media metrics in 10 minutes",
  objectives: ["Explain CPM, CPC and CTR", "Pick the right KPI for a goal"],
  modules: [deck, quiz],
});

export function Course() {
  return <LessonPlayer lesson={lesson} onComplete={(c) => console.log(c.score, c.passed)} />;
}
```

See [Build a multi-step lesson](./lessons.md) for every lesson field and player prop.

## Vite

Nothing special is needed. Import the stylesheet in `main.tsx` and use the components. Vite handles the CSS import and tree-shakes unused modules from the ESM build.

## Next.js (App Router)

Nibblearn components use state, effects and browser APIs, so they must render in a client component. Importing the package in a server component is safe (the import has no side effects beyond CSS), but rendering must happen on the client.

```tsx
// app/layout.tsx (server component is fine for the stylesheet)
import "@nibblearn/react/styles.css";
```

```tsx
// app/lesson/LessonClient.tsx
"use client";

import { LessonPlayer } from "@nibblearn/react";
import lesson from "./lesson.json";

export function LessonClient() {
  return <LessonPlayer lesson={lesson} />;
}
```

Progress storage is SSR-safe: `createLocalStorage()` probes `window.localStorage` on each call and falls back to memory when it is unavailable, so the player does not throw during server rendering or in private browsing. Pages Router works the same way; wrap the player in a component that is only rendered on the client (or use `next/dynamic` with `ssr: false` if you want to skip the server pass entirely).

## TypeScript autocompletion

Use the `Input` types with `satisfies` to author content in `.ts` files:

```ts
import type { ChoiceChallengeInput, LessonInput } from "@nibblearn/react";

export const quiz = {
  id: "kpi-quiz",
  type: "choice-challenge",
  content: {
    questions: [
      {
        prompt: "Which KPI measures **efficiency**?",
        options: [
          { text: "Impressions" },
          {
            text: "Cost per acquisition",
            correct: true,
            explanation: "CPA ties spend to results.",
          },
        ],
      },
    ],
  },
} satisfies ChoiceChallengeInput;

export const lesson = {
  schemaVersion: 1,
  id: "kpi-lesson",
  title: "KPIs",
  modules: [quiz],
} satisfies LessonInput;
```

`defineLesson(lesson)` then returns a fully typed, validated `Lesson` with all defaults applied, or throws `LessonValidationError` whose message lists every issue with its JSON path:

```text
• modules[0].content.questions[0].options: each question needs at least one correct option
```

## What `NibblearnProvider` is for (optional)

Modules and the player work with no provider at all. Add `NibblearnProvider` when several modules on one page should share settings:

```tsx
import { NibblearnProvider, Flashcards, TrueFalse } from "@nibblearn/react";

<NibblearnProvider locale="en" theme="dark" accent="#0ea5e9" onEvent={(e) => track(e)}>
  <Flashcards config={deck} />
  <TrueFalse config={statements} />
</NibblearnProvider>;
```

| Prop                                      | Purpose                                                                                                                |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `locale`, `messages`                      | UI language (English built in) and string overrides or translations. See [Accessibility and i18n](./accessibility.md). |
| `theme`, `accent`, `radius`, `fontFamily` | Light/dark/system and brand tokens. See [Theming](./theming.md).                                                       |
| `reducedMotion`                           | Force reduced motion regardless of OS preference.                                                                      |
| `onEvent`                                 | Receives every event from every module inside. See [Events](./events.md).                                              |
| `className`, `style`                      | Applied to the `.nb-root` wrapper element.                                                                             |

`LessonPlayer` creates its own provider internally (using the lesson's `language` and `theme`), so you only need an outer provider to override those or to collect events for several players at once.
